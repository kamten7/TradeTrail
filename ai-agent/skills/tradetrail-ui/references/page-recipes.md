# TradeTrail 页面配方与调用约定

本页按现有页面提供维护参考，布局尺寸和 token 以源码为准，不要求每页套同一个骨架。

## 商品与购物车

用户端使用商品卡片、数量交互、购物车勾选和收货表单。结算先显示服务端报价，提交 `items/expectedPriceCents/address`；改价或购物车变化时明确引导重新确认，不静默采用用户未确认的价格。

店家端复用 [ProductsPage](../../../../frontend/merchant/src/pages/ProductsPage.vue) 的查询、表格及表单，创建、编辑、上下架、库存调整分别表达业务动作。金额输入与展示区分整数分和元，调整库存必须填写原因。

商品图、批量操作、导出等当前未实现能力，不为占位设计空按钮。

## 订单与物流

参考 [用户订单页](../../../../frontend/customer/src/pages/OrdersPage.vue) 和 [店家订单页](../../../../frontend/merchant/src/pages/OrdersPage.vue)。主订单、付款结果、售后和物流分区展示；收货地址及明细使用成交快照。

物流展示运单与实际节点，不虚构预计送达。重复或迟到事件按服务端返回展示，不能由前端重新推导更高的履约状态。确认、取消、发货按钮的可见性不替代后端状态检查。

## 售后与恢复

参考 [AfterSalesPage](../../../../frontend/merchant/src/pages/AfterSalesPage.vue) 和 [RecoveryPage](../../../../frontend/merchant/src/pages/RecoveryPage.vue)。区分申请、审核理由、寄回运单、验收与退款结果；合格回补和退款成功是不同事实。

失败退款沿原退款号重试，outbox 人工队列只展示耗尽自动重试的任务。列表为空不代表系统没有待处理事件；提示文案不要扩大已知范围。

## 统一状态与可访问性

| 状态 | 页面处理 |
|---|---|
| 初次加载 | 适合当前区域的 loading 或骨架，避免同时显示“无数据” |
| 空列表 | 解释当前筛选或尚无记录，提供可行操作 |
| 加载失败 | 展示统一错误信息和重试；保留用户已填写内容 |
| 写入中 | 标记当前操作，防止重复点击；依靠请求层和后端保证幂等 |
| 业务拒绝 | 使用服务端原因，引导刷新报价、重新登录或查看售后 |

表单使用组件库标签和验证，图标按钮提供文字或可访问名称。移动端检查不横向溢出、操作区不遮挡内容、焦点与键盘可用。错误包含 traceId 时供诊断，不显示完整 Cookie、token 或签名。

物流页保持独立服务端表单、CSRF 和投递结果展示，不接入商城浏览器会话。完整页面验收在[测试与调试](../../../../docs/testing.md)。
